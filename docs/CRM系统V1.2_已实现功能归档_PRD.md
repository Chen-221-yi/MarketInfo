## 一、项目背景与建设目标

CRM 系统面向土地项目和长期客户关系维护场景，不是标准销售 CRM，也不围绕报价、合同、订单、销售漏斗展开。系统核心是“人”和围绕人的长期业务关系沉淀：联系人会调岗、换单位、进入不同项目，但关系信息、拜访记录、项目线索和社会关系仍需要持续追踪。

当前 V1.2 归档版本是在原 V1 PRD、V1.1 迭代以及 2026-06-15 会议优化基础上的功能现状留档。6-15 会议中演示和讨论的标签、相册、微信持有人、私密画像、社会关系、拜访生成情报线索、单位行政区划展示、首页最新动态、项目联系人关系变更等主要功能，在当前代码和表单配置中已有对应实现或部分实现。

本文档用于说明当前系统已经具备什么功能、入口在哪里、页面展示哪些信息、用户可以执行哪些操作、核心数据之间如何关联，并为后续编写用户操作手册提供结构化依据。

## 四、项目联系人关系模块

### 4.1 业务含义

项目联系人关系用于解决一个项目可能受到多个关键联系人共同影响的问题。它连接“项目档案”和“联系人”，记录某人在具体项目中的角色、影响程度、态度、熟悉程度、我方熟悉人、关键诉求、维护策略和下一步动作。

该对象强调“项目上下文中的关系”，不是联系人真实社会关系。例如：某局长在 A 项目中是决策人、态度支持；同一个人在 B 项目中可能只是信息源或协调人。

### 4.2 与联系人、项目的关系

| 关系 | 当前实现 |
| --- | --- |
| 联系人到项目 | 联系人详情“关联项目”Tab 读取项目联系人关系表，展示该联系人参与或影响的项目 |
| 项目到联系人 | 项目详情“关键联系人”Tab 读取项目联系人关系表，展示该项目的关键人员 |
| 关系变更 | 项目详情“联系人变更”Tab 读取关系状态、日期和变更说明；首页“最新动态”聚合关系变更 |

### 4.3 当前支持记录的关系信息

| 字段 | 用途 |
| --- | --- |
| 关联项目 | 指向项目档案，说明该关系属于哪个项目 |
| 关联联系人 | 指向关键联系人，说明项目涉及哪个人 |
| 联系人当前单位、联系人当前岗位 | 记录该联系人在关系发生时的单位和岗位快照 |
| 项目角色 | 标识牵头、决策、影响、协调、信息源、执行、阻力等角色 |
| 影响程度 | 以 5 星到 1 星记录对项目的影响强弱 |
| 当前态度 | 记录支持、中立、观望、反对、未知 |
| 熟悉程度 | 记录不认识、认识、熟悉、关系好、核心关系 |
| 我方熟悉人 | 记录公司内部熟悉该联系人的人员 |
| 关键诉求 | 记录该联系人在项目中的关注点、诉求和顾虑 |
| 维护策略 | 记录后续如何推进关系 |
| 最近沟通记录 | 可关联最近拜访记录 |
| 下一步动作 | 记录围绕该联系人的后续动作 |
| 授权查看人 | 标识可查看该项目关系信息的人员 |
| 记录人、记录时间 | 记录关系信息维护来源 |

### 4.4 生命周期与变更字段

2026-06-17 预发布 Schema 中，项目联系人关系已增加生命周期字段：

| 字段 | 当前选项或用途 |
| --- | --- |
| 关系状态 | 当前、已结束 |
| 生效日期 | 表示该项目关系开始生效的时间 |
| 结束日期 | 表示关系结束或不再适用的时间 |
| 变更说明 | 描述关系调整原因，例如岗位调整、负责人变更、态度变化等 |
| 变更类型 | 新增、角色变更、态度变更、移除、负责人变更 |

首页最新动态会聚合项目联系人关系记录，并优先使用结束日期、生效日期、记录时间、修改时间等作为排序依据。项目详情页同时提供“关键联系人”和“联系人变更”两个 Tab，分别用于查看当前项目关键人员和关系生命周期变化。

## 八、情报线索模块

### 8.1 业务定义

情报线索不是联系人资料补充，也不是私密画像。当前系统中，情报线索用于记录围绕项目机会、市场信息、政策动向、招采节点和后续跟进形成的市场信息。

如果信息属于长期人物档案，例如家庭情况、兴趣爱好、办公习惯、老乡同学关系，应进入私密画像或社会关系；如果信息属于某次拜访后发现的市场机会、政策节点、项目可能性或招采时间，应进入情报线索。

### 8.2 当前支持的核心字段

| 字段 | 用途 |
| --- | --- |
| 情报标题 | 用一句话概括线索 |
| 情报内容 | 记录具体市场信息或项目机会 |
| 情报分类 | 市场信息、项目线索、政策动向、招采节点、其他 |
| 重要程度 | 高、中、低 |
| 跟进状态 | 待跟进、跟进中、已转项目、已归档 |
| 跟进负责人 | 指定后续跟进人员 |
| 预计发生时间 | 描述线索可能发生的时间点 |
| 有效期截止日期 | 表示线索有效期，过期后需要复核 |
| 提醒日期 | 用于后续提醒和首页待处理排序 |
| 来源类型 | 拜访获得、电话/微信、公开信息、AI扫描、其他 |
| 来源拜访记录 | 关联产生该线索的拜访记录 |
| 关联联系人 | 线索涉及的联系人 |
| 关联项目 | 线索涉及的项目 |
| 下一步动作 | 记录后续跟进行动 |
| 权限级别、授权查看人 | 标识线索敏感程度和授权范围 |
| 记录人、记录时间 | 记录信息来源和维护人 |

## 九、首页与最新动态

### 9.1 首页整体结构

首页当前为工作台式布局，包含：

| 区域 | 当前展示 |
| --- | --- |

| 拜访超期/即将超期 | 最多展示 4 位风险联系人，按下次拜访截止日期排序 |
| 最近拜访记录 | 最多展示 4 条拜访记录 |

### 9.2 最新动态规则

首页“最新动态”当前聚合三类数据：

| 动态类型 | 来源 | 标题与摘要 |
| --- | --- | --- |
| 拜访记录 | 拜访记录表 | 使用拜访主题作为标题，摘要拼接联系人、拜访方式、下一步动作 |
| 项目更新 | 项目档案表 | 使用项目名称生成“有新进展”标题，摘要优先取最近进展、下一步动作、当前卡点、关键推进信息 |
| 项目联系人变更 | 项目联系人关系表 | 使用项目名称生成“联系人变更”标题，摘要拼接联系人、关系状态、变更说明或变更类型 |

动态排序规则：按各类记录可取得的最新时间倒序排列。项目联系人关系优先使用结束日期、生效日期、记录时间、修改时间和创建时间；项目更新优先使用最近更新日期；拜访记录使用修改时间、创建时间、拜访时间和记录时间。系统会按分组键去重，最多保留 8 条；首页面板默认展示前 3 条。

6-15 会议中提出的“有新的拜访记录、项目管理更新要在首页展示，有小红点提醒”的诉求，在当前首页代码中已有最新动态、未读红点和标记已读逻辑。该提醒为首页内展示逻辑，未核对钉钉待办或外部消息推送。

### 9.3 首页布局优化目标

当前首页使用网格布局组织超期、拜访、最新动态、资料完整度、重要日期、项目推进、情报线索等模块，目标是让横向和纵向模块对齐、信息密度合理、面板风格统一，并保持移动端自适应。
